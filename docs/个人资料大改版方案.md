## 1. 你要解决的问题

1. 档案内容要大幅扩容（参考页有 19 个段落：身份/体测/联络/职务/教育/交通/兴趣/网络资产/生活/饮食/健康/居住/财务/证件/背景/应急/设备/出行/大事记）。
2. 未来资料会从**随手记 AI 对话**等零散渠道持续追加到某个人身上。
3. 担心：预设字段太多后，档案页**编辑模式会不会卡顿**。
4. 设想：资料不再按字段/模块进数据库，而是**按“个人信息”整体存档**，甚至生成一个静态页（`rjgx/姓名+手机号/index.html` 或 `rjgx/姓名+手机号.html`）。

## 2. 三条存储路线对比

| 维度 | A. 纯 R2 静态 HTML（你的设想） | B. 纯数据库字段化（每段一张表） | **C. 混合：结构化核心 + 自由段落 JSON + R2 快照（推荐）** |
|---|---|---|---|
| 新增段落/字段 | 永远不用改库 | 每次都要迁移 + 改表单 | **永远不用迁移**（段落=JSON 数据，渲染器只有 6 种） |
| 生日提醒 / A-Z 列表 / 记一笔选人 / 财务关联 / AI 记忆 | ❌ 全部失效（HTML 不可查询） | ✅ | ✅（这些核心字段留在原表） |
| 随手记 AI 追加资料 | 要解析改写整页 HTML，易冲突 | 每字段单独映射 | ✅ 对某段 JSON 做 append/patch，最自然 |
| 打开速度 | 快（一个静态文件） | 一般（多次请求） | 快（段落列表一次请求，纯 HTML 渲染很轻） |
| 离线/备份/打印 | ✅ 整个文件夹拷走即走 | ❌ | ✅ 一键生成快照到同一文件夹，效果同 A |
| 安全 | 用户 HTML 同源展示有 XSS 风险，需沙箱 | 无 | 快照由系统生成（白名单渲染器），站内查看走鉴权路由 |
| 编辑体验 | 重建整页，冲突风险大 | 表单爆炸（你担心的卡顿） | **单段编辑器**：一次只编辑一段，与段落数量无关 |

**结论：不二选一。** 你的“按个人信息整体存档”的诉求，本质是要 **schema-free（结构自由）** 和 **可携带（文件夹拷走即走）**——这两点用“段落 JSON 存储 + R2 快照生成”都能拿到；而“纯 HTML 存档”会牺牲掉系统里已经跑通的一切联动（生日提醒、列表速查、记账关联人、AI 记忆），不划算。

## 3. `rjgx/姓名+手机号/index.html` 还是 `rjgx/姓名+手机号.html`？

**推荐 `index.html`（放文件夹里）**，理由：

1. **附件就在同一个文件夹**（`rjgx/姓名+手机号/` 已是现行约定）。档案页用相对路径 `./车照.jpg` 引用照片，**整个文件夹下载后双击 index.html 即可离线看完整档案（含照片）**；单文件版做不到，要么丢图要么用绝对 URL（拷走就断链）。
2. R2 没有目录列表，“一个人一个文件夹 + index.html 主文件”的语义最清晰；改名（姓名/手机号变更）时整体目录迁移，引用关系不变。
3. 单文件 `姓名+手机号.html` 只适合“纯文字、无多媒体”的极简档案，作为对比方案保留但不推荐。

> ⚠️ 注意：R2 不是网站，这个 index.html **不能**直接当公开网址访问。站内通过鉴权路由流式打开（如 `/api/profile/dossier?id=1`），也提供“下载整卷”按钮。你手机/电脑上看到的效果和直接开一个网页一样。

## 4. 推荐方案详设（C 路线）

### 4.1 数据模型：一张「段落表」吃下所有扩展

```sql
CREATE TABLE contact_sections (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  contact_id  INTEGER NOT NULL REFERENCES contacts(id) ON DELETE CASCADE,
  sec_key     TEXT NOT NULL,        -- identity/body/contact/vehicle/health/timeline…（自由）
  title       TEXT NOT NULL,        -- 段落标题，如「体测与尺码」
  badge       TEXT,                 -- 右上角角标，如「机密」「量体记录」
  secret      INTEGER DEFAULT 0,    -- 1=整段敏感（默认遮罩，点「揭示」可见）
  sort        INTEGER DEFAULT 0,    -- 段落排序（拖拽）
  data        TEXT NOT NULL,        -- JSON 载荷（见 4.2）
  updated_at  TEXT DEFAULT (datetime('now','localtime'))
);
```

- **每段一行**，`data` 是 JSON；新增 19 个段落 = 插 19 行，**零迁移、零新表**。
- 现有结构化模块（联系方式、职业、教育、家庭关系、宠物、身高体重、财务往来、附件）**原样保留**——它们承担提醒、筛选、联动；卷宗页里这些模块既可继续由原表渲染，也可叠加自由段落。

### 4.2 六种渲染器（吃遍 1.html 的全部版式）

| 渲染器 | data 形状 | 用途示例 |
|---|---|---|
| `kv` | `[["键","值",敏感?],…]` | 身份标识、联络方式、证件 |
| `list` | `[["名称","说明"],…]` | 兴趣爱好、目标清单 |
| `table` | `[["表头…"],["行…"],…]` | 体测尺寸表、设备清单 |
| `tags` | `["标签",…]` | 授权范围、技能标签 |
| `bars` | `[["名称",百分比],…]` | 能力雷达、目标进度 |
| `tl` | `[["时间","事件"],…]` | 大事记时间线 |
| `cards`（新增） | `{照片附件id, kv 行…}[]` | 交通工具：一辆车一张卡，可挂该人附件里的车照 |

> 渲染器在**服务端/前端共用一份白名单实现**，用户数据只能以纯文本进模板（自动转义），不存在自由 HTML 注入。

### 4.3 录入：单段编辑器（这就是不卡的关键）

- 档案页查看模式默认**渲染全部段落**（纯 HTML，轻）；点某段标题栏的「编辑」→ 只弹出**这一段**的编辑器（kv 段=键值行编辑，list 段=两列行编辑……），保存即合入，**局部刷新该段，不再整页 reload**（顺带修掉“每添加一条就刷新页面”的老问题）。
- 编辑器 DOM 恒定几十个节点——**段落再多（哪怕 100 段）编辑体验不变**。
- 新建段落：从预设模板选（身份/体测/联络/…/大事记）或自定义标题，选渲染器，开填。

### 4.4 随手记 AI → 追加到某人档案

- 随手记识别出 `relation` 草稿时，除现有建档/更新外，支持 `sections` 追加指令，例如：
  - “张伟 2026-11 换新号 139××××” → 联络方式段 append 一行（带来源与日期）；
  - “张伟上周提了主管” → 职务段 append + 大事记 append 一条时间线；
  - 拍照识别名片 → 新建联系人 + 自动开「联络方式」段。
- AI 只产出**结构化 JSON patch**，人点确认后落库（沿用 v0.5.27 的“AI 预填弹窗人工确认”模式）。

### 4.5 展示：卷宗风格 + 双端响应式

- 档案页在现有模块之后新增**「档案卷宗 Dossier」**区块：牛皮纸底、宋体、黑标题条、机密红章、敏感字段黑条遮罩（点「揭示/隐藏机密」全局切换）、左侧锚点目录。
- 桌面端：左侧 200px 目录 + 右侧卷宗（同 1.html）；手机端：目录变横滑锚点条，卡片单列。
- 夜间模式跟随全站主题（预览页已实现日夜双套配色）。

### 4.6 R2 快照：「生成档案页」

- 卷宗区块右上角「⬇ 生成档案页」→ 服务端把全部段落渲染成**独立 ES5 静态 HTML**（样式即 1.html 风格），照片/附件用相对路径 `./xxx`，写到 R2 `rjgx/姓名+手机号/index.html`。
- 站内「查看快照」走鉴权路由流式返回；「下载整卷」= 把该人文件夹内对象逐个打包下载（或提示用 rclone 拉取）。
- 快照是**手动生成**的存档点（带生成时间戳），平时编辑只写数据库，避免每次编辑都重写 R2。

## 5. 性能分析（直接回答“会不会卡”）

| 场景 | 现状/如果按字段硬扩 | 改版后 |
|---|---|---|
| 打开档案页 | 全模块一次渲染 | 段落=一次 SQL 拉全 + 纯 HTML 拼接；100 段也在 10ms 级 |
| 编辑模式 | 现在已是“全模块控件同时展开”，硬扩 19 组字段后 DOM 上千节点、每次保存整页 reload（你已反馈过的卡） | **永远只编辑一段**，DOM 恒定，保存局部刷新 |
| 随手记追加 | 无处安放，字段越多表单越堵 | JSON patch 一行确认，不碰表单 |
| 数据库体积 | 列爆炸 | 每人几行 JSON，极小 |
