## v0.2.4 迭代：修编辑报错 + 个人中心按钮居中

需求：1) 点击习惯「编辑」报 `⚠ 页面出错：Promise: method is not defined`；2) 侧栏底部个人中心按钮文字相对按钮未居中。

### 根因与修复
- **method is not defined**：v0.2.3 改造时把 `const method = ...` 写在了 `editHabit` 的 `else` 块内，但块外的 `syncMethodUI(method, h.unit)` 仍要访问它 → 出块即 ReferenceError。修复：把 `const method = isSleep ? 'count' : (...)` 提到 if/else 之前（函数作用域）。同时把 `fillUnitOptions` 调用去掉（`syncMethodUI` 内部已会调 `fillUnitOptions`，避免重复渲染）。
- **按钮文字未居中**：`.side-bottom` 自身有 `border-top:1px` + `padding-top:14px`，而 `.nav-item` 是固定 `height:44px`，border/padding 挤压内容导致「图标+文字」行偏下。修复：把分隔线和上间距移到父容器 `.side-bottom-wrap`（`padding-top:14px; border-top:1px`），`.side-bottom` 去掉 border/padding 并显式声明 `display:flex;align-items:center;justify-content:flex-start;gap:12px;height:44px;padding:0 13px;box-sizing:border-box`。
- 版本号 0.2.3 → 0.2.4；SW 缓存 v5 → v6。

### 教训
- **JS 块级作用域**：`const/let` 声明在 `if/else` 块内，块外不可见。改造函数时若把变量声明收进分支、又要在块外使用，必然抛 ReferenceError。语法检查（node --check）查不出这类错误，必须核对作用域。
- **固定高度 + border/padding**：给固定 `height` 的元素加 border/padding 会压缩内容盒（除非显式 `box-sizing:border-box`），视觉上表现为「内容不居中」。

## Git 推送免弹窗配置（SSH）

问题：每次 `git push` 都弹 Git 凭据确认框（HTTPS + wincred 未存到 GitHub 凭据），且每次推送耗时 2~40 分钟。

解决（用户选择 SSH 方案）：
1. `ssh-keygen -t ed25519 -f .ssh-keys/id_ed25519 -N ""`（放在项目内，因沙箱禁写 ~/.ssh）。
2. 公钥添加到 GitHub：https://github.com/settings/ssh/new
3. `git config core.sshCommand "ssh -i <abs>/.ssh-keys/id_ed25519 -o IdentitiesOnly=yes"`（仓库级）。
4. `git remote set-url origin git@github.com:zwjdujin/shuzishenghuo.git`。
5. `ssh-keyscan github.com >> ~/.ssh/known_hosts`。
6. `.gitignore` 增加 `.ssh-keys/` 与 `*.pem`。

验证：`ssh -T git@github.com` 返回 `Hi zwjdujin!`；`git push` **3.6 秒**完成，零弹窗。

**安全要点**：私钥仅存本地 `.ssh-keys/`（已忽略），仓库内密钥文件数为 0。
**踩坑**：首次 `ssh-keygen` 因 `cd ~/.ssh` 权限被拒，改在项目内生成；失败命令在项目根目录误留 id_ed25519 密钥文件且未被忽略，已删除。

## 修复：SSH 推送仍弹窗（读取 ~/.ssh/known_hosts 被拦截）

现象：改用 SSH 后推送虽成功，但每次仍弹出「读取 C:/Users/Administrator/.ssh/known_hosts 命中安全中心规则」确认框（用户已选"始终允许"仍弹）。

根因：SSH 每次连接都要读 `~/.ssh/known_hosts` 验证主机密钥，而 `~/.ssh/` 目录被 WorkBuddy 安全中心保护，故每次触发询问。这是**文件访问拦截**，不是 Git 的凭据询问——所以「始终允许」对该规则无效。

修复（彻底隔离 `~/.ssh`）：
1. `ssh-keyscan github.com > .ssh-keys/known_hosts`（生成到项目内，不触碰受保护路径）。
2. `: > .ssh-keys/ssh_config`（空配置，配合 `-F` 阻止读取 `~/.ssh/config`）。
3. 仓库 `core.sshCommand`：
   `ssh -F "<abs>/.ssh-keys/ssh_config" -i "<abs>/.ssh-keys/id_ed25519" -o IdentitiesOnly=yes -o UserKnownHostsFile="<abs>/.ssh-keys/known_hosts" -o GlobalKnownHostsFile=NUL`
   - `-F` 空配置 + `UserKnownHostsFile` + `GlobalKnownHostsFile=NUL` 三者共同保证不再访问 `~/.ssh/`。

验证：连续 3 次推送均约 4.2 秒，无任何 `~/.ssh` 读取提示。

**教训**：WorkBuddy 环境下 `~/.ssh/` 属受保护路径，"始终允许"选项对其无效。SSH 相关文件一律放项目内目录（如 `.ssh-keys/`），并显式用 `-F`/`-o UserKnownHostsFile`/`-o GlobalKnownHostsFile=NUL` 屏蔽默认路径查找。
