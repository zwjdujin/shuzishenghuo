## 日历中心改版 v0.3.11 → v0.3.12

### 用户需求
1. 周历标题 `10月4日 - 10月10日 · 第2026年` → `当前为YYYY年第N周`；右侧上一周/下一周（月历才是上一月/下一月）。
2. 周历时间改为纵列 0:00–23:00 从上到下，点某小时可新增日程，兼顾手机端。
3. 月历 `#calViewBox` 高一点，日期方格平均拉高铺满 1920×1080 视口（考虑浏览器标题栏/地址栏/收藏栏），刚好不出现滚动条。

### 🔴 排查到的真正根因：周历「时间轴横向乱排」
`.cal-week-grid` 原本是 `display:grid;grid-template-columns:44px repeat(7,1fr)`，而 `.cal-hour`（本身就是 8 列 grid、内部含刻度+7 格）被当作**外层 grid 的一个格子**塞进去 → 15 个整行在 8 列里横排换行，实测 `cal-week-grid = 1130x98`（2 行 × 8 列），7 天列被压到 ~100px。这就是用户说的「时间要改为纵列」。
**修法**：`.cal-week-grid` 改 `display:flex;flex-direction:column`，`.cal-hour` 才是 8 列 grid。

### 实现
- `app.js`：`weekOfYear()`（以「含 1/1 的周日那一周」为第 1 周，与周日～周六区间一致）；`renderCalView()` 新标题 + 副标题 `#calEyebrow`；`syncCalNavLabels()` 按视图改 `#calPrev/#calNext` 的 title+aria-label；`buildWeekView()` 重写（24 行 0–23 点、`.cal-allday` 全天行、sticky 表头/刻度列、`.now` 当前小时格）；`fitCalView()` + resize 防抖。
- `style.css`：新增整屏自适应链（`#view-calendar.active{display:flex}` + `.cal-panel/#calViewBox/.cal-month-wrap{flex:1;min-height:0}` + `.cal-month-grid{grid-auto-rows:minmax(0,1fr)}`）；周历 `--cal-hcol/--cal-gap/--cal-row/--cal-minw`（桌面 46/6/22/0，手机 38/4/30/640px 横向滚动）；手机端工具栏压缩尺寸（head 204→138px）。
- `index.html`：eyebrow 加 `id="calEyebrow"`。
- 版本 0.3.11→**0.3.12**，SW CACHE `v24`→`v25`。

### 🔴 `fitCalView()` 是本次的核心手法
`innerHeight − (scrollY + rect.top) − .main-content 的下 padding` 实测写入 inline height → 页面总高恰等于视口高，**刚好无滚动条**，且自动适配浏览器 chrome 与手机动态地址栏（写死 `100vh - N` 做不到）。桌面 1920×1080 月历方格 158×163 铺满；1024×700 / 1366×768 / 1440×900 / 2560×1440 全部无滚动条。

### 踩坑
- **`.cal-week-grid` 误加 `min-height:0`** → 网格被压到小于 24 行最小高度，12:00–23:00 既不可见也**不可滚**（滚动容器 scrollHeight 不反映溢出）。必须保持 `min-height:auto`。
- **手动起的预览页自身注入 `!important`**（`.view.active{display:block!important}`）盖掉了 `#view-calendar.active{display:flex}`，一度误判「自适应没生效」→ 生成页注入样式只留 `*{transition:none!important}`。
- **模板字符串里 `\d` 被吞成 `d`**：生成页里的 `#month-2026-8` 正则静默失效，排查了半天。反引号内写正则必须 `\\d`。

### 工具
新增 `scripts/gen-calpreview.mjs`（加载真实全套脚本、只换 `window.fetch` 喂样例数据）+ `scripts/shot-cal.mjs`（多视口几何报告+截图）+ `scripts/test-calendar.mjs`（**25 项断言**：24 行/竖排/点 9:00 周一预填 `T09:00`/上下周 ±7 天与周序/月历语义与铺满/6 行月份/夜间亮底巡检/窗口变矮重算）→ 全通过。`test-theme`(18 色)/`test-medicines`(20)/`test-data-api`(27) 回归通过。

## 22:2x 账户安全新增「修改密码」（v0.3.13）

需求：个人中心 → 账户安全，在「退出登录」**下方**加修改密码；版本末位 +1。

### 核心取舍：密码为什么必须落库
管理员密码原本只来自 Cloudflare 环境变量 `ADMIN_PASS`，**运行时无法改写** → 「修改密码」无处可存。
方案：自定义密码写入 D1 `app_settings.admin_pass_hash`（PBKDF2-SHA256 / 10 万次迭代 / 16 字节盐，
格式 `pbkdf2$iter$salt$hash`，恒定时间比较）。**`verifyAdminPassword()` 库中有哈希就优先，没有才回退环境变量**
→ 一旦改过密码，环境变量里的初始密码立即失效。`data/export.js` 显式排除该键（备份会被下载/转发）。
`app_settings` 在「清空所有数据」时本来就保留，所以密码不会因清空而丢。

### 后端
- `functions/_lib.js` +5 个导出：`hashPassword`/`verifyPassword`/`verifyAdminPassword`/`readCustomPassHash`/`saveCustomPassHash`/`ADMIN_PASS_KEY`。
- `functions/api/auth/password.js`（新增，受中间件保护）：校验旧密码、长度 6–64、两次一致、新旧不同；
  成功后 `DELETE FROM sessions WHERE sid != 当前sid` 踢掉其它设备，当前设备保留。
- `login.js` 改 `verifyAdminPassword`；`sessions.js` GET 加 `customPass`。

### 🔴 顺手挖出的隐患（比本次需求更重要）
`app.js` 末尾所有 `$('#id').addEventListener` **都无空值保护**。`#changePassBtn` 加进 index.html 后，
早先生成的 `_preview/calpreview.html`（HTML 快照不含该元素）里 `$('#changePassBtn')` 返回 null →
`addEventListener` 抛错 → **该 script 内之后的全部顶层代码都不执行**（`restoreAppearance()`、`boot()`…），
表现为日历页首屏几何全是 0x0、`#calNext` 不可见、`test-calendar.mjs` 报 Timeout。
→ 新增绑定统一改走 `bind(sel, type, fn)`（内部 `if (el)`），并写进 MEMORY：
**改完 index.html 必须重新生成所有 `_preview/` 体检页**。

### 验证

  改密后新旧密码行为 / 二次改密覆盖 / 会话踢除且当前保留 / customPass 标记 / 备份无 `pbkdf2$` / 会话表异常不阻断 / 库中无明文）。

  390×844 与 1440×900、日间与夜间实测：两钮等宽且修改密码在下、弹窗在视口内、错误提示与成功提交流程正常、
  无横向溢出、无页面报错。
- 回归：`test-theme`(18 色)、`test-medicines`(20)、`test-data-api`(27)、`test-calendar`(25) 全过。

## 19:4x 我的账本全面增强（v0.3.14）

需求：账本页「支出构成」显示异常（含图表）；在原有基础上充实账本功能，兼顾手机端与其它页联动（人情账）；版本末位 +1。

### 🔴 核心 bug：环图被压成 20×20 的小点
`style.css:110` 的 **全局 `svg{width:20px;height:20px;...}`（给图标用）** 优先级高于 SVG 元素自身的
`width="160" height="160"` **表现属性**（presentation attribute 属作者级、特异性 0），
于是整个甜甜圈被缩成 20×20 → 页面上只剩中间一点彩色 + 一大堆图例。
headless 实测 `<svg>` 渲染尺寸 `20×20`（`viewBox=0 0 160 160`，circle 的 `getBBox()` 仍是 120×120 → 说明几何没坏，只是被 CSS 缩了）。
**修法**：环图尺寸一律由 `.donut-svg` 的 CSS 显式给出（特异性 0,1,0 > 0,0,1）。
→ 记进 MEMORY：**页面里要渲染「真正的图形 SVG」（图表/示意图）时，必须用 CSS 类显式给宽高，
不能依赖 `width`/`height` 属性；否则会被全局图标规则吃掉。**

### 顺带发现并修掉的既有手机端缺陷
`.modal-card input{max-width:100%;width:100%}`（为输入框铺满整行）**也会匹配 `.seg-item` 里的 radio**，
把它撑成整行宽 → 「支出 / 收入」「按次打卡 / 按时间打卡」文字被挤成竖排两行。
修法：`.seg-item input[type="radio"]{width:auto;height:auto;flex:0 0 auto;...}`
（属性选择器特异性 0,2,1 > `.modal-card input` 0,1,1，与书写位置无关，故放在基座 CSS 即可）。
